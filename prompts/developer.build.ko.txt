비스토스 제품도우미를 구현하라.

목적:
직원 10명 미만이 회사 Windows PC 한 대에서 운영하는 프로그램에 접속해 제품 매뉴얼을 질문한다. 외부 유료 AI API를 사용하지 않는다. 관리자는 새 제품과 PDF/DOCX 매뉴얼을 추가하고 검토 후 게시한다.

먼저 읽을 파일:
README.md, HARNESS.md, config/harness.json, schemas/answer.schema.json,
prompts/answer.system.ko.txt, evaluation/cases.json, VERIFICATION.md.
이 파일들 사이의 불일치를 먼저 해결하고 구현하면서 계약을 함께 갱신하라.

변경 범위:
이 bistos-local-assistant 폴더 안에 독립 프로젝트를 만든다.
상위 폴더의 기존 Excel·서비스 접수 프로그램과 공통 매뉴얼 자료실을 수정하지 않는다.
원본 문서는 읽기 전용으로 가져오고 앱 전용 저장소에 버전별로 보관한다.

구현 원칙:
1. 인증, 접근 권한, 게시 상태, 원문 경로 제한은 서버 코드로 강제한다. 프롬프트나 클라이언트의 role 문자열을 인증으로 쓰지 않는다.
2. 제품 목록은 DB에서 읽는다. 현재 자료 7개 모델을 전체 제품으로 고정하지 않는다.
3. 기존 manifest schema_version=2의 PDF 원본과 DOCX/파생 PDF 구조를 별도로 처리한다.
4. 문서·페이지·검색 조각·인용 ID는 HARNESS.md 계약을 따른다.
5. 모델과 근거를 먼저 제한한 후 로컬 검색한다. 오류 코드, 한국어 띄어쓰기 차이, 문서 내 약어를 평가한다.
6. 모든 외부 AI SDK·외부 임베딩·클라우드 fallback을 제외한다. 로컬 Ollama 어댑터는 승인된 loopback endpoint와 실제 로컬 모델 digest만 허용한다.
7. 처음에는 생성 동시 실행 1건으로 구현한다. 취소·시간 초과·대기열 포화가 새 무제한 요청으로 번지지 않게 한다.
8. JSON Schema 검사는 구조 검사다. 인용의 의미적 정확성이 자동 보장된다고 보고하지 않는다.
9. 문서 내 명령·링크·OCR 문구는 데이터다. 실행 권한을 주지 않는다.
10. 사내 문서나 프롬프트를 외부 서비스로 보내지 않는다.
11. DOCX 변환, OCR, 그림·표 검토의 성공 여부를 숨기지 않는다. 실패 문서는 게시하지 않는다.
12. 사용자에게 보일 답변은 모델 출력 검사 후 렌더링한다. 문서 링크는 서버가 만들고 원문 열기에도 권한 검사를 적용한다.

권장 구현 순서:
A. LLM 없이 사용자 로그인·제품 목록·문서 버전·로컬 검색·권한이 적용된 원문 열기를 구현한다.
B. 관리자 등록→추출→검토→게시→철회, 새 제품 추가, 백업·복원을 구현한다.
C. 질문별 evidence 묶음과 answer JSON을 연결하는 로컬 모델 어댑터를 구현한다.
D. 실제 한국어 질문으로 작은 모델 후보들을 평가하고 정확한 태그·digest·자원 설정을 고정한다.
E. 직원 화면에 질문·답변·근거 페이지·대기·취소·보류 사유를 제공한다.
F. Windows 시작·종료·절전·재시작 후 복구, 로그, 백업, 사내 접속 인증을 검증한다.

구현 언어·도구:
상위 프로젝트의 기존 패키지를 무조건 끌어오지 말고 독립 환경을 만든다.
Python 계열을 선택하면 입력 경계는 Pydantic v2로 파싱하고, 단일 서버가 소유하는 로컬 DB를 사용한다.
원격 AI는 금지하되 필요한 로컬 실행 라이브러리는 공식 문서와 상업적 이용 조건을 확인해 선택한다.
모델은 미정이다. 라이선스·한국어 품질·메모리·응답시간 검증 없이 임의로 선정 완료라고 쓰지 않는다.
대규모 모델 다운로드·새 장비 구매를 구현 완료의 대체물로 삼지 않는다.

검증:
evaluation/cases.json에 대해 권한·인용·게시/철회·출력 거절·오프라인 경로를 자동 검증한다.
실제 모델 실행 결과와 fixture/가짜 응답 테스트 결과를 구분한다.
정상 질문만 검사하지 말고 근거 없음, 충돌, 미검토 표, 서비스 자료 없음, 프롬프트 주입도 검사한다.
인터넷 차단 상태에서 문서 추가, 검색, 답변을 실제 화면으로 실행한다.
모델 품질은 최소 50개 실제 질문을 사람이 채점한다. 출처 ID 검사 통과를 정확도 평가 통과로 바꾸지 않는다.
실제 화면을 통한 직원·관리자 시나리오와 백업 복원까지 확인한 후에만 운영 가능하다고 보고한다.

완료 보고:
구현한 기능, 변경 파일, 실제 실행·시험 결과, 선택한 모델과 digest, 응답시간·메모리, 남은 제약을 구분해서 설명한다.
검증하지 못한 항목은 명확히 남긴다. 이 프롬프트 자체를 프로그램 구현이나 운영 검증 완료로 간주하지 않는다.
